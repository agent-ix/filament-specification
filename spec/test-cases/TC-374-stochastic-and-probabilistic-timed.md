# TC-374: Stochastic delays, timed sampling and exact digital checking

## Description

Sample stochastic timed models with exact rational delays, and check probabilistic timed automata exactly through digital clocks or clock regions.

## Test Procedure

Run each vector through the real local Rust boundary of the frontend or provider named by the requirement, and compare the complete typed result (value, cause and payload) with the expected result.

## Models

The models below are defined here in full; the citation names the FSL design record each one comes from. `ev` selects `filament.temporal.event-position.false-extension/v1`, `inf` selects `filament.temporal.infinite-trace/v1` and `timed` selects `filament.temporal.timed/v1`.

- **`Rpc`**, **`NoLateReply`** and **`Settles`** (from FSL ADR-026 §11). `time Rpc dense unit ms;`. One object `c: Call { phase: Phase, inflight: Boolean, late: Boolean, x: Clock }`, `Phase` one of `Idle`, `Waiting`, `Replied` and `TimedOut`; universe `{c}`; initially `phase = Idle`, `inflight` and `late` false, `x = 0`. `Call::send` has pre `phase = Idle` and post `phase = Waiting`, `inflight`, `not late` and `x = 0`. `Call::reply` has pre `inflight and x >= 1 ms` and post `not inflight`, `late = (pre(phase) = TimedOut)`, and `phase = Replied` when `pre(phase) = Waiting`, unchanged otherwise. `Call::timeout` has pre `phase = Waiting and x >= T` and post `phase = TimedOut`. `Call::reset` has pre `not inflight and (phase = Replied or phase = TimedOut)` and post `phase = Idle`. The time invariants are `x <= 3 ms` while `inflight` and `x <= T` while `phase = Waiting`. `T` is a time constant each vector fixes. `NoLateReply` is `temporal NoLateReply using inf over (k: Rpc::Call) clock "model-steps" on origin { always holds(not k.late) }`. `Settles` is `temporal Settles using timed over (k: Rpc::Call) clock "model-time" on origin { always (holds(k.phase = Waiting) implies eventually[0 ms, 3 ms] holds(k.phase != Waiting)) }`.
- **`Retx`**, **`Deadline`** and **`MeanTime`** (from FSL ADR-028 §15.5). `time Retx dense unit ms;`. One object `m: Msg { delivered: Boolean, x: Clock }`, initially `delivered = false` and `x = 0`. `Msg::send(lost)` has pre `not delivered and x >= 1 ms` and post `delivered = not lost and x = 0`, with `random Msg::send(lost) ~ { true: 1, false: 9 };` and no `delay` declaration. The time invariant is `x <= 2 ms` while `not delivered`. A state with `delivered` is terminal. `Deadline` is `probabilistic Deadline using timed on Retx under every scheduler on origin { probability >= 0.99 [ eventually[0 ms, 4 ms] holds(m.delivered) ] }`. `MeanTime` is `probabilistic MeanTime using timed on Retx under every scheduler on origin { expected elapsed until holds(m.delivered) <= 3 ms }`.
- **`RareLate`** (from FSL ADR-026 §11). `Rpc` with `T = 3 ms`, starting from the state just after `send` (`phase = Waiting`, `inflight`, `late` false, `x = 0`), with `delay Call::reply ~ discrete { 1 ms: 90, 3 ms: 10 };`, `delay Call::timeout ~ uniform;`, `delay Call::send ~ exponential(rational(1, 1000));`, `delay Call::reset ~ exponential(rational(1, 1000));` and `workload Even on Rpc { weight Call::send = 1; weight Call::reply = 1; weight Call::timeout = 1; weight Call::reset = 1; }`. Its claim is `probabilistic RareLate using timed on Rpc under Even on origin with alpha 0.01, beta 0.01, indifference 0.005 { probability <= 0.01 [ eventually[0 ms, 3 ms] holds(c.late) ] }`, run with seed `20261001`. `timeout`'s window from the start is the single point 3 ms, so the event holds exactly when `reply` draws 3 ms and the tie is ordered `timeout` first: its exact probability is `1/10 · 1/2 = 1/20`.
- **`Send`**, **`Idle`** and **`Tick`**. One object `c: Call { phase: Int[0, 2] }`, initially `phase = 0`. `Call::send` has pre `phase = 0` and post `phase = 1`. `Send` is `time Send dense unit ms;` with `delay Call::send ~ discrete { 2 ms: 1 };`, `Call::reply` (pre `phase = 1`, post `phase = 2`), `delay Call::reply ~ discrete { 10 ms: 1 };` and a workload of weight 1 on each operation. `Idle` is `Send` without `reply`. `Tick` is `time Tick tick Call::tick period 2 ms unit ms;` with `send`, an operation `Call::tick` with pre and post `phase = 2`, no `delay` declaration and a workload of weight 1 on each. Each claim is over `(c: M::Call)`, `using timed`, `on origin`, with `alpha 0.4, beta 0.4, indifference 0.05`, run by the fixed-sample method (`N = 184`) with seed 7.
- **`Split`**. `time Split dense unit ms;`. One object `c: Gate { phase: P, x: Clock, z: Clock }`, `P` one of `Start`, `Early`, `Late` and `Done`, initially `phase = Start` and both clocks 0, with no `delay` declaration and no workload. `Gate::first(late)` has pre `phase = Start`, resets `z`, and sets `phase = Late` when `late` and `Early` otherwise, with `random Gate::first(late) ~ { true: 1, false: 1 };`. `Gate::early` has pre `phase = Early and z >= 1 ms` and `Gate::late` has pre `phase = Late and x >= 1 ms`; each sets `phase = Done`. Time invariants: `x <= 1 ms` while `phase` is `Start` or `Early`, and `z <= 0 ms` while `phase = Late`. With `first` at time `t` in `[0, 1]`, `Early` finishes only when `t = 0` and `Late` only when `t = 1`; every other run time-locks.
- **`Burst`**. `Idle` with `delay Call::send ~ discrete { 0 ms: 1 };`.
- **`Overtake`**. `time Overtake dense unit ms;`. One object `c: Gate { phase: P, z: Clock }`, `P` one of `Init`, `Lost`, `SB`, `CDone` and `DDone`, initially `phase = Init` and `z = 0`, `z` never reset, with no time invariant. `Gate::a` has pre `phase = Init`, sets `phase = Lost` and has `delay Gate::a ~ discrete { 1 ms: 1 };`. `Gate::b` has pre `phase = Init`, sets `phase = SB` and has no `delay` declaration. `Gate::c` has pre `phase = SB`, sets `phase = CDone` and has `delay Gate::c ~ discrete { 1 ms: 1 };`. `Gate::d` has pre `phase = SB and z >= 1 ms`, sets `phase = DDone` and has no `delay` declaration. `workload W on Overtake` gives each of the four weight 1. On dense time `b` at `1/2` ms beats `a`, and `d` at `z = 1` beats `c`, which fires at `3/2` ms, so `DDone` is reached with probability 1. At integer times `b` at 0 leaves `d` to tie with `c`, and `b` at 1 ties with `a`, so the maximum is `1/2`.
- **`Skew`**. `time Skew dense unit ms;`. One object `c: Gate { phase: P, x: Clock, g: Clock }`, `P` one of `Start`, `U`, `V1`, `V2` and `End`, initially `phase = Start` and both clocks 0, with no `delay` declaration and no workload. `Gate::go(late)` has pre `phase = Start`, resets `x`, and sets `phase = V1` when `late` and `U` otherwise, with `random Gate::go(late) ~ { true: 1, false: 1 };`. `Gate::stop` has pre `phase = U and g >= 1 ms` and sets `phase = End`; `Gate::enter` has pre `phase = V1 and g >= 1 ms` and sets `phase = V2`; `Gate::leave` has pre `phase = V2 and x >= 1 ms` and sets `phase = End`. Time invariants: `g <= 1 ms` while `phase` is `Start`, `U` or `V1`, and `x <= 1 ms` while `phase = V2`. With `go` at `t` in `[0, 1]`, the time spent in `U` or `V2` within `[0, 2]` is `1 - t` on one branch and `t` on the other. At `t = 1/2` both branches reach `1/4` of the window, so the probability that the `weighted by delay` fraction is at least `1/4` is 1; at integer `t` exactly one branch does, so it is `1/2`.
- **`Pinch`**. `time Pinch dense unit ms;`. One object `c: Gate { phase: P, x: Clock, z: Clock }`, `P` one of `Start`, `Mid` and `Done`, initially `phase = Start` and both clocks 0, `x` never reset, with no `delay` declaration and no workload. `Gate::first` has pre `phase = Start`, resets `z` and sets `phase = Mid`; `Gate::low` has pre `phase = Mid and x <= 0 ms` and `Gate::high` has pre `phase = Mid and x >= 1 ms`, each setting `phase = Done`. Time invariants: `x <= 1 ms` while `phase = Start`, and `z <= 0 ms` while `phase = Mid`. `first` at `t = 0` or `t = 1` reaches `Done`; at any `t` strictly between, the run time-locks. So the expected elapsed time to `Done` has an infinite maximum, while at integer times it is at most 1 ms.
